# Manual configuration log

Spec §0.3: *every service is defined in code; nothing is configured only
through a web UI without a note here explaining what was clicked and why.*

This file is that note. It ships pre-seeded with the settings the spec says
cannot be expressed in the repo. Work top to bottom, tick the box, and fill in
**Date** and **Value / what was actually set** as you go — an unticked box is a
build step that has not happened yet, not a formality.

Legend: `LAN` = needed for the current LAN-mode rollout · `TAILNET` = needed
only for the §5.2 tailnet phase · `HOST` = done on the Proxmox host, not in the
LXC.

## 1. Prowlarr indexers — **operator decision, not a build step** (§13)

- [ ] Done — Date: `____-__-__`

**Where:** Prowlarr → Indexers → Add Indexer (`http://<host>:9696`)

**What must be clicked:** whatever the operator decides. Prowlarr ships with no
indexers and the build leaves it that way.

**Why this is not automated:** spec §13 is binding. The agent does not select,
configure, or recommend indexers, and no indexer is named anywhere in this
repo. The stack is source-agnostic — it behaves identically against Internet
Archive collections, public-domain film libraries, Creative Commons material,
Linux distribution trackers and paid Usenet providers. Automation raises
acquisition volume substantially over manual use, and under Malaysian law this
sits with the Copyright Act 1987, with ISPs acting on rightsholder notices.
Indexer selection is therefore the single point where the deployment's legal
profile is determined, which is why it belongs to the operator alone.

**Record what was configured (operator fills in):**

| Date | Indexer/source added | Reason | Added by |
|------|----------------------|--------|----------|
|      |                      |        |          |

**Then:** Prowlarr → Settings → Apps → add Sonarr and Radarr so indexer
definitions sync outward. That wiring *is* mechanical; the sources are not.

## 13. qBittorrent auth-bypass subnet whitelist

- [x] Done — Date: `2026-08-12` — **security-relevant, read before redeploying**

**Where:** `${CONFIG_ROOT}/qbittorrent/qBittorrent/qBittorrent.conf`
(container stopped first — qBittorrent rewrites this file on exit and would
have discarded a live edit). Original saved alongside as `.bak`.

```
WebUI\AuthSubnetWhitelist=172.20.0.0/16
WebUI\AuthSubnetWhitelistEnabled=true
```

**What it does:** clients whose source address is on the `medianet` Docker
bridge reach the qBittorrent Web API without logging in. Radarr and Sonarr
therefore hold **no qBittorrent credentials at all** (entry 4's download client
has empty username/password fields). LAN clients — phones, laptops, the browser
on `:8080` — are unaffected and still need the login.

**Why this over storing the password twice:** the *arr apps would otherwise
persist the qBittorrent password in their own databases, which are then inside
the nightly backup archive. Scoping trust to the internal bridge keeps the
secret in one place. Chosen by the owner on 2026-08-12 over the
type-the-password-manually alternative.

**⚠ The subnet is environment-specific.** `172.20.0.0/16` is what Docker
Desktop assigned `medianet` on the Windows dev box. On the Proxmox LXC the
bridge will almost certainly get a different subnet, and a stale value here
means the *arrs get 403s from a client that tests fine by hand. On redeploy:

```bash
docker network inspect medianet --format '{{range .IPAM.Config}}{{.Subnet}}{{end}}'
```

then update the two lines above to match.

**To revert:** set `WebUI\AuthSubnetWhitelistEnabled=false` (container stopped),
restart it, and add the qBittorrent username/password to the download client in
both Radarr and Sonarr.

**Verified:** from a container on `medianet`,
`curl http://qbittorrent:8080/api/v2/app/version` → `200 v5.2.3` with no
credentials; both `POST /downloadclient/test` calls returned 200.

## 15. `homelab-rescan.timer` — addon index reconciliation (O4)

- [ ] Done — Date: `____-__-__` — **LXC only; cannot be installed on the Windows dev box**

**Where:** inside LXC 101, alongside `homelab-backup.*`

```bash
chmod +x /opt/homelab/scripts/rescan.sh
cp /opt/homelab/systemd/homelab-rescan.{service,timer} /etc/systemd/system/
systemctl daemon-reload && systemctl enable --now homelab-rescan.timer
systemctl start homelab-rescan.service    # prove it once
journalctl -u homelab-rescan -n 20
```

**Why:** spec open item O4. Jellyfin watches the filesystem and self-heals
within ~2 minutes; the addon indexes only at startup and on demand, so anything
changed outside an addon rescan leaves it stale — a deleted file keeps a stream
URL pointing at nothing. Observed live on 2026-08-12: a movie deleted in Radarr
vanished from Jellyfin on its own, while the addon still served it until
`rescan.sh` ran and took the index from 1 row to 0.

**Runs every 15 min** (`OnUnitActiveSec=15min`, plus `OnBootSec=3min`), not
persistent — a missed run has no value once the next one is due.

**Optional companion:** Radarr/Sonarr → Settings → Connect → Webhook →
`http://addon:7000/admin/rescan` with the bearer token gives *instant* refresh
on import, but fires only on *arr events and so misses hand-dropped or
hand-deleted files. The two compose fine; the rescan is idempotent.

**On the dev box** the script runs by hand from the repo (verified working);
there is no systemd in Docker Desktop, so the timer itself waits for the LXC.

## 16. Jellyfin API key + *arr → Jellyfin instant library refresh

- [x] Done — Date: `2026-08-12`

**Where:** Jellyfin → Dashboard → API Keys (key named `arr-notifications`), then
Radarr/Sonarr → Settings → Connect → Emby/Jellyfin (added via
`POST /api/v3/notification`).

**What was set** — identical in both apps:

| Field | Value |
|-------|-------|
| Host / Port | `jellyfin` / `8096` (container name on `medianet`) |
| Update Library | on |
| Send Notifications | off (no client popups) |
| Triggers | On Import, On Upgrade, On Rename, On Delete |

Both `POST /notification/test` returned 200 before saving.

**Why:** Jellyfin's own filesystem watcher already self-heals, but only after
`LibraryMonitorDelay=60` plus scan time — about 2 minutes, measured. This pushes
a targeted refresh the moment an import finishes, so a new file is playable
immediately instead of a couple of minutes later. Delete triggers are on for the
same reason in reverse.

**The key lives in the Radarr/Sonarr databases**, not in `.env` — it was created
in Jellyfin and pasted straight into both apps. To rotate: delete it in
Jellyfin → API Keys, create a new one, and update both notification entries.

**Note — the addon has no equivalent.** Radarr's Webhook connection only offers
HTTP Basic auth, while `/admin/rescan` requires `Authorization: Bearer`, so the
*arrs cannot call the addon directly without either a custom script inside the
container or weakening the addon's auth. Neither is worth it: entry 15's
15-minute timer covers the addon, and it also catches hand-dropped files that no
*arr event would ever fire for.

**§13 note.** Entry 1 remains the standing rule: the agent does not select

here. If a new indexer seems missing in the *arrs, that is why.

## 18. Windows Firewall + network profile — **dev box only**

- [x] Done — Date: `2026-08-12` — **does not apply to the LXC**

**Where:** elevated PowerShell on the Windows host

```powershell
Set-NetConnectionProfile -InterfaceAlias "Ethernet" -NetworkCategory Private
New-NetFirewallRule -DisplayName "Jellyfin LAN" -Direction Inbound -Protocol TCP `
  -LocalPort 8096 -Action Allow -Profile Private
New-NetFirewallRule -DisplayName "Homelab LAN" -Direction Inbound -Protocol TCP `
  -LocalPort 80,7878,8989,9696,8080,6767 -Action Allow -Profile Private
```

**Why the profile line matters most:** Windows classifies new wired networks as
`Public`, which blocks inbound traffic regardless of any `-Profile Private`
rule. Both rules above were created first and were completely inert until the
adapter was reclassified — the rule existing is not evidence that it applies.
Check with `Get-NetConnectionProfile` before debugging anything else.

**Verified after the change:** all six ports listen on `::` (dual-stack, so IPv4
LAN clients connect), while the addon remains bound to `127.0.0.1:7000` only —
§6.5's loopback guarantee survives the firewall being opened.

**Not needed on the LXC:** there is no host firewall in the container, and
tailnet access does not traverse one. This entry exists so the dev box's
behaviour is not mistaken for something the production deployment requires.

## 19. URL bases on every app — single-origin routing

- [x] Done — Date: `2026-08-12`

**Where:** each app's own settings, then `caddy/Caddyfile`

| App | Setting | Value |
|-----|---------|-------|
| Jellyfin | Dashboard → Networking → Base URL | `/jellyfin` |
| Radarr | Settings → General → URL Base | `/radarr` |
| Sonarr | Settings → General → URL Base | `/sonarr` |
| Prowlarr | Settings → General → URL Base | `/prowlarr` |
| Bazarr | Settings → General → Base URL (`general.base_url`) | `/bazarr` |
| qBittorrent | *none — has no such setting* | Caddy strips its prefix instead |

**Why:** so every UI is served from one origin over one certificate, instead of
`host:port` links to a second hostname. Caddy uses `handle` (not `handle_path`)
for all but qBittorrent — the prefix must reach the app or it serves its HTML
and 404s its own assets.

**⚠ THIS BREAKS INTERNAL WIRING — every integration that talks to these apps
must carry the base path too.** Four broke on 2026-08-12, all silently:

| Integration | Fix |
|-------------|-----|
| Radarr/Sonarr → Jellyfin notification | `urlBase` = `/jellyfin` (was 400ing) |
| Prowlarr → Radarr/Sonarr apps | `baseUrl` = `http://radarr:7878/radarr`, `…/sonarr` |
| Addon `RADARR_URL` / `SONARR_URL` | append `/radarr`, `/sonarr` in `.env`/compose |
| Seerr → Radarr/Sonarr | `baseUrl` field per server (entry 20) |

None of them errored visibly — the addon just fell back to Cinemeta and the
notifications stopped refreshing the library. If something looks subtly wrong
after touching a URL base, this is the first thing to check.

**Also:** a `202` from the *arr config PUT persists `UrlBase` to `config.xml`
but does **not** reload it. The container must be restarted or the app keeps
serving at the old root.

## 21. Docker Desktop start-on-login — **dev box only**

- [ ] Done — Date: `____-__-__` — **currently OFF**

**Where:** Docker Desktop → Settings → General → *"Start Docker Desktop when
you sign in to your computer"*

**Why it matters:** every container is `restart: unless-stopped`, so once the
engine is up the whole stack returns by itself — verified by a full
`compose down` / `up` cycle that reached serving in **12 seconds**, with the
`media` node keeping its tailnet IP. But none of that happens if Docker itself
never starts.

The signals disagree on this box: `settings-store.json` reports
`AutoStart = False` while an `HKCU\...\Run` entry exists. Rather than infer,
set the toggle explicitly.

**Even then it starts at _login_, not at boot.** A remote power-cycle leaves the
machine at the lock screen with nothing running. Enable auto-login if that
matters, or accept it — LXC 101 has no such limitation, which is part of why
the spec targets Proxmox.
